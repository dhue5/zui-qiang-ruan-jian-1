# 最强软件2 开发者重建手册

本文说明“最强软件2”的搭建框架与代码原理，目标是让开发者可以从本仓库重建出一模一样的软件。

## 1. 总体架构

软件是一个桌面应用，采用前后端分离但打包在同一个进程中的结构：

```text
React/Vite 前端 (dist, 打包进 Tauri)
        │  window.__TAURI_INTERNALS__.invoke(...)
        ▼
Tauri 2 (Rust) 命令层 commands.rs
        │
        ├── 提示词库 prompts.rs（纯内存数据，无 I/O）
        ├── SQLite 数据层 db.rs（会话、消息、笔记、画布、任务）
        ├── OpenAI 兼容聊天 stream_chat_raw（reqwest + SSE）
        └── 媒体/文件命令（media、导出、下载）
```

关键点：

- 前端只负责界面和交互，所有持久化、网络请求放在 Rust 侧。
- 数据库使用 SQLite（rusqlite bundled），无需外部数据库服务。
- 聊天使用 OpenAI 兼容协议，可指向任意兼容服务商。
- 生产版本不依赖 `localhost:1420`，`frontendDist` 直接内嵌 `dist`。

```text

```

## 3. 数据层原理（db.rs）

数据放在操作系统应用数据目录，目录名与 `tauri.conf.json` 的 `identifier` 保持一致：

```text
%APPDATA%\<identifier>\
  chats.db          SQLite 主库
  settings.json     媒体目录、聊天 API 回退配置等
  media\            生成媒体文件
```

核心表（`init` 函数建立）：

- `conversations`：会话（id、title、created_at、updated_at、model）
- `messages`：消息（conversation_id、role、content、模型、媒体字段、deleted 软删）
- `notes`：笔记（标题、内容、时间戳）
- `canvases`：画布（标题、内容、时间戳）
- `generation_tasks`：生成任务（状态、进度、模型、请求、结果）

设计要点：

- 会话和消息支持软删除，确保历史数据可恢复。
- 所有时间戳使用毫秒整数，排序稳定。
- `task_db()` 会在主库不可用时回退到内存库，保证程序可用。
- `is_path_allowed` 限制文件读写只允许在应用数据目录和媒体根目录内。
- `settings.json` 保存 `media_root`、`chat_api_key`、`chat_base_url` 等。

## 4. 命令层原理（commands.rs）

所有后端功能通过 `#[tauri::command]` 暴露，前端用 `invoke(command, args)` 调用。

命令分组：

- 提示词组合：`get_prompt_categories_safe`、`get_thinking_methods_safe`、`get_output_formats_safe`、`compose_system_prompt`、`compose_prompt_preview`
- 会话/消息：`create_conversation`、`list_conversations`、`get_conversation`、`get_conversation_messages`、`save_message`、`update_conversation_title`、`delete_*`、`search_*`、`export_conversation_markdown`
- 媒体：`get_media_root_path`、`set_media_root_path`、`get_media_files`、`delete_media_file`、`rename_media_file`、`get_local_image_path`、`save_audio_cover`、`save_video_thumbnail`
- 笔记：`create_note`、`get_note`、`get_note_list`、`update_note`、`delete_note`、`export_note_markdown`
- 画布：`create_canvas`、`get_canvas`、`get_canvas_list`、`update_canvas`、`delete_canvas`
- 聊天：`stream_chat_raw`、`cancel_chat`
- 生成任务：`submit_generation_task`、`cancel_generation_task`、`get_pending_tasks`、`check_timeout_tasks`、`generate_media`、`cancel_media_generation`
- 文件/更新：`read_external_file`、`download_and_save_world_model`、`download_update_with_auth`、`check_update_with_token`
- 健康检查：`db_health_check`、`debug_log`

## 5. 聊天流原理（stream_chat_raw）

1. 前端调用 `stream_chat_raw`，传入消息、模型、API Key、Base URL、温度、最大长度、思考强度。
2. Rust 组装 OpenAI 兼容请求：

```text
POST {base_url}/chat/completions
{
  "model": ...,
  "messages": [{"role": "system", ...}, ...],
  "temperature": ...,
  "max_tokens": ...,
  "max_completion_tokens": ...,
  "reasoning_effort": "high",
  "stream": true
}
```

3. 以 SSE/流式读取响应，逐行解析 `data:` 事件。
4. 识别 `choices[0].delta.content` 或 `reasoning_content`，通过 Tauri 事件转发：

```text
chat-raw-chunk  增量数据
chat-raw-end    结束
chat-raw-error  失败
```

5. 前端监听这些事件，把内容追加到气泡中。
6. `cancel_chat` 通过原子标志 `CHAT_CANCEL` 中止当前流。

设计要点：

- 同时发送 `max_tokens` 和 `max_completion_tokens`，兼容不同服务商参数。
- 默认 `reasoning_effort=high`、`max_tokens=32768`，追求高质量、长输出。
- API Key 优先使用前端传入，其次使用 `settings.json` 的 `chat_api_key`。
- 生产包不应把密钥硬编码在源码里。

## 6. 提示词库原理（prompts.rs）

内置提示词目录由 `build_catalog()` 在内存中构建，不访问数据库：

| 类别 ID | 名称 | 条目 |
| --- | --- | --- |
| music | 音乐生成 | udio_trailer（Udio 预告片配乐） |
| audio | 音频特效 | sfx（音效描述） |
| image | 图像生成 | midjourney、character_profile |
| video | 视频分镜 | storyboard_cn、dialogue、scene_extract |
| 3d | 3D 世界 | world |

每个条目包含：

- `base_prompt`：基础角色/任务提示词
- `thinking_prompt`：深度思考协议
- `output_prompt`：输出格式约束

思考方式：

- `thinking`：深度思考（内置长思考协议）
- `none`：无思考

输出格式：

- `udio_prompt`、`midjourney_prompt`
- `chinese_storyboard`、`dialogue_storyboard`
- `scene_list`、`character_sheet`

组合逻辑（`compose`）：

```text
[base_prompt]

[thinking_prompt]   （选择“深度思考”时）

[output_prompt]     （选择输出格式时）
```

规则：

- 必须至少选择一种思考或输出，否则返回错误。
- 输出格式只在条目自身绑定了输出约束时追加。
- 内置提示词是纯文本，便于后续扩展和本地化。

## 7. 前端与后端交互

前端通过 Tauri 全局对象调用后端：

```js
await window.__TAURI_INTERNALS__.invoke("compose_system_prompt", {
  categoryId: "image",
  itemId: "midjourney",
  thinkingId: "thinking",
  outputId: "midjourney_prompt",
});
```

前端本地状态保存在 WebView localStorage，例如：

- `provider-configs`：服务商与模型配置
- `prompt-selector-selection-v2`：提示词选择记忆
- `current-conversation-id`：当前会话
- `chat-drafts`：草稿

## 8. 数据库与本地配置

`settings.json` 字段：

- `media_root`：媒体文件根目录
- `chat_api_key` / `chat_base_url`：聊天 API 回退配置
- `media_base_url` / `media_api_key`：媒体生成配置
- `auto_install_updates`：自动更新开关
- `update_manifest_url`：更新清单地址

## 9. 构建与发布

环境要求：

- Node.js 20+
- Rust stable（MSVC）
- Visual Studio Build Tools（MSVC + Windows SDK）
- Tauri CLI（`npm i -g @tauri-apps/cli` 或 `npx @tauri-apps/cli`）

```powershell
npm install
npx tauri build
```

产物位置：

```text
src-tauri/target/release/bundle/nsis/最强软件2_1.0.x_x64-setup.exe
```

版本号需同步修改：

```text
package.json
package-lock.json
src-tauri/Cargo.toml
src-tauri/Cargo.lock
src-tauri/tauri.conf.json
```

应用标识保持固定为 `com.zuiqiangruanjian.desktop`，这样 NSIS 安装新版时会识别为同一软件并覆盖升级。

## 10. 从头复刻一份同样软件的步骤

1. 克隆本仓库。
2. 安装上述环境。
3. 把 `package.json`、`Cargo.toml`、`tauri.conf.json` 中的名称和标识改成自己的产品名。
4. 运行 `npm install`。
5. 检查 `prompts.rs` 中的提示词，按需替换或扩展。
6. 运行 `npx tauri build` 生成安装包。
7. 将安装包放入 `releases/`。
8. 如需自动升级，实现 `update_manifest_url` 指向的清单服务。

## 11. 安全注意事项

- 不要把真实 API Key 提交到公开仓库。
- `node_modules/`、`src-tauri/target/` 已加入 `.gitignore`。
- 允许的文件路径被限制在应用数据目录和媒体根目录。
- 公共分发给第三方前，建议让每台电脑单独填写 API Key，或通过代理中转。

`src-tauri/src/db.rs` 和 `prompts.rs` 内置单元测试，可运行：
